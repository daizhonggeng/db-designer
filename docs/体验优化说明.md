# 第一版体验优化

本轮从第一次使用、日常编辑、恢复工作三个环节优化，保留原有界面风格和数据库逆向、AI、SQL 导出能力。

## 建议体验路线

1. 打开本地 `http://127.0.0.1:5173`，注册自己的账号。登录页不再展示不存在的演示账号。
2. 新建项目，选择「订单示例」。会带入客户、订单、订单明细三张表及两条关系；也可以选择空白项目。
3. 双击表头修改字段，点「保存更改」应用到画布。输入框里的 Ctrl+Z 保留文本撤销功能，关闭有修改的表编辑器会先提醒。
4. 停止操作约 1.5 秒后自动保存。项目名下方显示保存状态；点项目名可以重命名。结构检查不会阻止保存尚未完成的设计。
5. 点「保存版本」或 Ctrl+S 创建一个可恢复的历史版本。自动保存只更新当前项目，不连续生成历史版本。
6. 导航栏可以按表名、字段名和中文注释搜索。按 F 或点画布右下角的「适应画布」显示全部表；工具栏可以隐藏导航栏。
7. 导出菜单中可下载 SQL、PNG、SVG 或 JSON 项目备份。工作台上的「导入项目备份」会从 JSON 创建独立项目；编辑器中的导入会在确认后替换当前画布，可撤销。
8. 返回工作台，点「继续上次编辑」会打开自己最近访问且有权限的项目。

## 数据恢复与协作

- 有未保存内容时，会在当前浏览器按账号、项目保存一份本机草稿。刷新或重新进入项目时可选择恢复；浏览器存储不可用时会明确提醒。
- 保存失败会显示错误、重试与下载备份入口，保留画布和草稿。恢复网络后可重试保存。
- 检测到另一窗口或协作者已保存新版本时，会停止覆盖并提示冲突。先下载当前 JSON 备份，再载入最新版本；需要保留草稿时可在恢复提示中选择。
- 载入历史版本会应用到画布，并遵循当前自动保存设置；可以通过撤销恢复。
- 项目保存与手动版本快照在同一个 SQLite 事务中完成。只持久化表、关系和书签，不再把撤销栈、剪贴板一起上传。
- 现有 SQLite 文件会自动补充更新时间和保存版本字段，账号、项目及历史版本保留。

## 修复的问题

- 最近项目入口原先按创建时间挑选，且可能选中未加入的项目。
- 切换项目原先会把上个项目带入撤销历史。
- 表结构编辑和字段标记修改原先无法正常撤销；编辑器中删除字段还可能留下关系引用。
- 再次编辑表时，索引及主键约束使用的字段引用、类型可能丢失；现在统一转换并保留。
- 画布平移后，拖动坐标重复扣除了偏移；关系线也仍使用旧表头高度。现在按实际字段位置计算。
- 新建表原先名称、位置都相同，连续新增容易重名或重叠。
- 工作台加载失败原先只有控制台日志，现在有错误提示和重试入口。取消协作申请弹窗也不会再提交申请。

## 验证与边界

- 自动化：运行 `npm --prefix server test`，覆盖 SQLite API、原有数据升级、保存冲突、事务回滚、备份格式、表编辑引用和画布坐标。
- 浏览器：走通注册、示例/空白创建、表编辑与撤销、自动保存、刷新恢复、保存冲突、断网重试、重命名、跨项目撤销隔离、最近访问、JSON 导入导出、SQL 和 PNG 导出、历史恢复。
- 在 1366×900 与 1280×800 视口检查主编辑流程及适应画布，无页面横向溢出。
- 本轮未调用真实 AI 服务，也未连接外部数据库验证逆向导入；这些既有功能仍需要对应服务配置。旧 PostgreSQL 数据不会在本轮自动迁入 SQLite。
- 本机草稿依赖当前浏览器存储；JSON 备份适合手动迁移或保留重要节点。协作目前通过保存版本检测冲突，没有实时合并编辑。
